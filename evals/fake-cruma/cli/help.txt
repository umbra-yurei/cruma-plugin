Establish a tunnel to cruma.io

Usage: cruma [OPTIONS] [COMMAND]

Commands:
  schema             Print the configuration file json schema
  start              Load tunnel targets from a configuration file (supports multiple targets)
  up                 Run the cruma.yaml (or cruma.toml) found in the current directory or a parent, up to the repository root or your home directory. Stops with an error when there is none; it never falls back to a profile or the default config
  proxy              Proxy traffic to a backend (http, https, tcp, or raw)
  serve              Serve a local directory as a static file server
  config             Manage configuration file
  secret             Manage secrets kept outside the discovered project file
  project            Work on the discovered project file (`cruma.yaml` / `cruma.toml`) itself
  profiles           List or pick the named profiles shared with the desktop app
  dashboard          Open the agent's local web dashboard in your browser, signed in without a password prompt
  open               Open the Cruma desktop app, or bring it forward when it is already running
  auth               Sign in to your Cruma account, show who this agent is signed in as, or sign out
  tunnel             List, create and switch between the tunnels of your Cruma account
  mcp                Serve the agent's MCP tools over stdio for a coding agent (Claude Code, Codex, ...). By default it uses a shared anonymous agent with nothing exposed; `--profile NAME` or `--agent ID` use an agent that is already running instead (and never start one)
  agent-context      Print your Cruma account's coding-agent session note (nothing when the board and memory are both off, or when not signed in). For a coding agent's session-start hook: it always exits 0
  show-cache         Show the cache directory location
  clear-cache        Clear the tunnel cache directory (removes cached identity and credentials)
  grant-port-access  Grant this binary permission to bind privileged (< 1024) ports without running as root (Linux: setcap cap_net_bind_service; requires elevation)
  help               Print this message or the help of the given subcommand(s)

Options:
      --tower-server <TOWER_SERVER>   Which server to connect to (default: tower.cruma.io:443). Examples:
      --headless                      Disable the interactive terminal UI and run in headless mode
      --tui                           Force the interactive terminal UI
      --minimized                     Start with the GUI hidden; only the tray icon is shown
      --theme <MODE>                  Set the theme mode: light, dark, or system (default: system)
      --generate-completions <SHELL>  Generate shell completions to stdout [possible values: bash, zsh, fish, powershell, elvish, nushell]
  -c, --config <PATH>                 Path to a configuration file to start with (shorthand for the 'start' subcommand)
      --profile <NAME>                Start with a named profile from the desktop app's Profiles page (see `cruma profiles list`)
      --temp                          Use a temporary identity and cache directory for this run
      --require-registered            Refuse to start unless the tunnel has registered credentials (never fall back to an anonymous tunnel)
  -h, --help                          Print help (see more with '--help')
  -V, --version                       Print version
